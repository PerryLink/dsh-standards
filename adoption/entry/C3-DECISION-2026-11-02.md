# C3 decision — flow-only (2026-11-02)

> 非官方 · 非认证 · 非排名 · 无 `verified`。这是 pilot 数据后的标准调整记录，不是市场结论。

## Data

- 30 个第三方样本（15 high / 10 mid / 5 edge）；15 个 C3 host install：
  - **14 pass / 0 fail / 1 blocked**（`zhoushoujianwork/easyeda-agent`：插件加载成功，运行时缺外部 CLI `easyeda`）。
  - 5 个 edge 是宿主/目录样本，C3 按协议 `not-applicable`。
- C3 没有区分度：15 个全部能安装；唯一 blocked 是环境缺外部依赖，不是插件不能装。
- 两个本地 tarball（`T-Auto/dsh-ops`、`elysia395/dsh-wallpaper-engine`）因未提交构建产物/workspace 子包出现 entry import 失败；从 registry 安装干净。C3 结论**依赖安装路径**，不能只凭本地 `npm pack` 判定。
- 静态 8 个 fail 全部来自 C1/C2/C6，与 C3 无关。

## Decision

- **C3 从 ENTRY 硬门槛降为 FLOW-only**：没有 `--host-evidence` 时 C3 = `not-applicable`，不再让 ENTRY 变 `incomplete`；J1 是 FLOW 的必跑项。
- **C1/C2/C6 不变**：8 个静态 fail 保持 fail。
- **`--host-evidence` 接受 `not-applicable`**：宿主/目录样本不会被误算成缺检查。
- **安全前置**：只对 `clean` / `mentions-only` 自动跑 C3；`install-hook` / `remote-install` / `destructive-prod` / `secrets-prod` 标 `requires-review`，不自动跑（advisory A6）。
- 不改插件来凑 pass；C3 的本地 tarball 与 registry 安装差异写进 FLOW 方法学。

## Re-run (same 30, C3 flow-only)

- Before C6 A7: `2 pass / 19 pass-with-warnings / 1 incomplete / 8 fail`.
- After C6 A7: `2 pass / 20 pass-with-warnings / 1 incomplete / 7 fail`; `adoresever/graph-memory` moved to A7.
- 7 fail: `GanyuanRan/Aegis` (description), `ilyautov/humanizer-ru` (C1 topic), edge 5.
- 1 incomplete：`zhoushoujianwork/easyeda-agent`（C3 blocked，外部 CLI 缺失）。
- 19 warnings 主要是 C4 未声明、C5 构建产物、C6 repository 等 advisory。

## Limits

- 没有 hold-out、没有独立 reviewer；样本 30 不是生态结论。
- 未改上游、未发 PR、未联系维护者、未公开失败插件名。
- 本记录只支持“C3 降为 FLOW”，不支持“ENTRY 已经稳定”或“市场认可”。
